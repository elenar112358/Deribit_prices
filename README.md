# Deribit prices

Сервис для периодического получения индексных цен криптовалют с криптобиржи Deribit, сохранения результатов в PostgreSQL и предоставления сохранённых данных через REST API.

## КРАТКО

### Запуск тестов

```bash
bash run_tests.sh
```

### Собрать образ и запустить сервисы

```bash
docker compose -f compose.yml up --build -d
```

## Возможности

- Получение индексных цен `btc_usd` и `eth_usd` через публичный JSON-RPC API Deribit Testnet.
- Автоматический сбор цен с периодичностью в одну минуту.
- Асинхронное выполнение фоновых задач с помощью Celery.
- Планирование периодических задач с помощью Celery Beat.
- Хранение валют и истории цен в PostgreSQL.
- Предоставление сохранённых данных через REST API на FastAPI.
- Управление схемой базы данных с помощью Alembic.
- Контейнеризация приложения и базы данных с помощью Docker Compose.

## Архитектура

Приложение состоит из API, слоя работы с данными и фоновой задачи сбора цен.

Основной поток обработки:

1. Celery Beat запускает задачу каждую минуту.
2. Celery Worker выполняет задачу получения цен.
3. Задача отправляет запросы к Deribit Testnet для `btc_usd` и `eth_usd`.
4. Полученные цены и временные метки сохраняются в PostgreSQL.
5. FastAPI предоставляет сохранённые данные по HTTP.

Redis используется как брокер сообщений между Celery Beat и Celery Worker.

### Контейнеры

Проект разворачивается в двух контейнерах (требование ТЗ):

- **app** — FastAPI, Celery Worker, Celery Beat, Redis и Supervisor.
- **postgres** — сервер PostgreSQL.

Supervisor запускает и контролирует процессы приложения внутри контейнера `app`. Redis работает в том же контейнере, поэтому отдельный контейнер для него не требуется.

PostgreSQL запускается отдельно. Данные базы сохраняются в Docker volume и не теряются при обычной остановке контейнеров.

## Настройка окружения

### 1. Создать файл `.env`
Для образца использовать .env.example

Значения выше соответствуют локальной конфигурации проекта. При необходимости замените пароль и другие значения на собственные.

**Важно:** файл `.env` содержит настройки и пароль базы данных. Не публикуйте его в открытом репозитории.

### 2. Как используются порты

| Параметр | Значение | Назначение |
|---|---:|---|
| `APP_PORT` | `8000` | Порт API на хостовой машине |
| `POSTGRES_PORT` | `5435` | Порт PostgreSQL на хостовой машине |
| Порт PostgreSQL в контейнере | `5432` | Внутренний порт PostgreSQL |
| Порт Redis внутри `app` | `6379` | Локальный брокер Celery |

Для Celery используется Redis по адресу `redis://localhost:6379/0`, поскольку Redis работает в том же контейнере, что и Celery.

## Тестирование

Для автоматического тестирования API используется **Pytest**. Тесты запускаются в отдельном Docker Compose-окружении с собственной базой данных PostgreSQL. Тестирование не использует основную базу данных приложения.

### Архитектура тестового окружения

Тестовое окружение описано в файле `compose.test.yml` и состоит из двух контейнеров:

- **`test`** — окружение для запуска Pytest.
- **`test_db`** — отдельный сервер PostgreSQL 18 Alpine с тестовой базой `ss_test_db`.

Параметры тестовой базы:

- База данных: `ss_test_db`.
- Пользователь: `test_user`.
- Внутренний порт PostgreSQL: `5432`.
- Порт на хостовой машине: `5433`.

Контейнер `test` подключается к базе по адресу `test_db:5432`. Запуск тестов зависит от состояния `healthy` контейнера `test_db`: готовность PostgreSQL проверяется с помощью `pg_isready`.

### Организация тестов

Тесты API находятся в директории `tests/`.

Файл `tests/conftest.py` содержит общие фикстуры и настройки тестового окружения:

- создание отдельного SQLAlchemy engine и фабрики сессий для тестовой базы;
- переопределение зависимости FastAPI `get_db`, чтобы запросы использовали тестовую базу;
- создание клиента `TestClient` для выполнения HTTP-запросов;
- создание таблиц перед тестами и удаление после них;
- подготовка тестовых данных для проверки API.

### Что проверяется

Автоматические тесты охватывают следующие уровни приложения.

**Обработка данных от биржи**
- Обработка мок-ответа Deribit без обращения к реальному API.
- Корректное извлечение цены из ответа биржи.
- Создание записи валюты в базе данных, если она отсутствует.
- Сохранение новой цены для существующей валюты.

**REST API**

Проверяются три эндпоинта:
- `GET /prices/` — получение цен валюты.
- `GET /last_price/` — получение последней цены валюты.
- `GET /date_prices/` — получение цен валюты за заданную дату.

Для каждого эндпоинта проверяются корректность возвращаемых данных и обработка запроса для несуществующей валюты с ответом `404 Not Found`.

**Сервисный слой**
- Проверка существования валюты и получение данных о ценах через сервисный слой.
- Корректная обработка запросов на получение истории цен, последней цены и цен за указанную дату.

**Репозитории**
- Проверка поиска валюты и получения её идентификатора.
- Создание записи валюты при необходимости.
- Сохранение новых записей с индексными ценами.
- Получение истории цен, последней цены и цен за указанную дату.

### Запуск тестов

Для запуска автоматических тестов используется скрипт `run_tests.sh`, который организует запуск тестового окружения в отдельных Docker-контейнерах.

Из корневой директории проекта выполнить:

```bash
bash run_tests.sh
```

Скрипт запускает тесты с помощью Pytest в изолированном окружении с отдельной базой PostgreSQL. Основная база данных приложения не используется для тестирования.

## Запуск через Docker Compose

Все команды этого раздела выполняются из корневой директории проекта, где находятся `Dockerfile` и `compose.yml`.

### 1. Проверить Docker

```bash
docker --version
docker compose version
```

Убедитесь, что Docker Desktop запущен.

### 2. Собрать образ и запустить сервисы

```bash
docker compose -f compose.yml up --build -d
```

Команда:

- собирает образ приложения;
- загружает образ PostgreSQL, если его ещё нет локально;
- создаёт сеть и Docker volume;
- запускает PostgreSQL;
- дожидается готовности PostgreSQL;
- запускает контейнер приложения;
- применяет миграции Alembic;
- запускает API, Celery Worker, Celery Beat и Redis под управлением Supervisor.

Флаг `-d` запускает контейнеры в фоновом режиме.

### 3. Проверить состояние контейнеров

```bash
docker compose -f compose.yml ps
```

Контейнер PostgreSQL должен иметь состояние `healthy`, а приложение — `running`.

### 4. Посмотреть логи приложения

```bash
docker compose -f compose.yml logs -f app
```

В логах можно проверить запуск API, Redis, Celery Worker и Celery Beat, а также выполнение миграций и фоновых задач.

Для выхода из режима просмотра логов нажмите `Ctrl+C`. Контейнеры при этом продолжат работать.

### 5. Посмотреть логи PostgreSQL

```bash
docker compose -f compose.yml logs -f postgres
```

### 6. Проверить API

Откройте документацию Swagger в браузере:

http://localhost:8000/docs

Также доступна схема OpenAPI:

http://localhost:8000/openapi.json

## Работа с API

### Получение сохранённой цены

Эндпоинт:

```http
GET /api/prices/?currency=btc_usd
```

Пример для BTC:

```bash
curl "http://localhost:8000/api/prices/?currency=btc_usd"
```

Пример для ETH:

```bash
curl "http://localhost:8000/api/prices/?currency=eth_usd"
```

Запрос возвращает сохранённые данные для указанной валюты. Структура ответа определяется схемой `PricesResponse` и включает:

- `currency` — тикер валюты;
- `price` — сохранённая цена;
- `timestamp` — временная метка Unix в секундах.

Пример структуры JSON-ответа:

```json
{
  "currency": "btc_usd",
  "price": 65000.12,
  "timestamp": 1790000000
}
```

## Проверка фоновых задач

### Посмотреть логи Celery Worker

```bash
docker compose -f compose.yml logs -f app
```

В логах ищите сообщения о запуске worker и выполнении задачи `app.tasks.price_task.fetch_prices`.

### Проверить выполнение расписания

Celery Beat запускает задачу сбора цен с интервалом 60 секунд.

После успешного запуска подождите до минуты и проверьте логи приложения. Убедитесь, что задача выполняется и сохраняет полученные значения без ошибок.

### Проверить доступность сервисов внутри контейнера

Открыть shell внутри контейнера приложения:

```bash
docker compose -f compose.yml exec app sh
```

Проверить доступность Redis:

```sh
redis-cli -h 127.0.0.1 -p 6379 ping
```

Ожидаемый ответ:

```text
PONG
```

Проверить доступность PostgreSQL из контейнера приложения:

```sh
pg_isready -h postgres -p 5432 -U postgres -d sql_base
```

Ожидаемый результат — сообщение о том, что сервер принимает подключения.

Выйти из shell:

```sh
exit
```

## Миграции базы данных

При штатном запуске контейнера `app` миграции применяются автоматически командой:

```bash
alembic upgrade head
```

Она выполняется в `docker/entrypoint.sh` после проверки готовности PostgreSQL и до запуска основных процессов приложения.

Чтобы вручную применить миграции в уже запущенном контейнере:

```bash
docker compose -f compose.yml exec app alembic upgrade head
```

Посмотреть текущую ревизию:

```bash
docker compose -f compose.yml exec app alembic current
```

Посмотреть историю миграций:

```bash
docker compose -f compose.yml exec app alembic history
```

## Управление контейнерами

Все команды ниже выполняются из корня проекта.

### Остановить контейнеры

```bash
docker compose -f compose.yml stop
```

Контейнеры остановятся, но останутся созданными. Данные PostgreSQL сохранятся.

### Повторно запустить остановленные контейнеры

```bash
docker compose -f compose.yml start
```

### Остановить и удалить контейнеры и сеть

```bash
docker compose -f compose.yml down
```

Named volume с данными PostgreSQL по умолчанию сохраняется.

### Пересобрать образ и обновить приложение

После изменения кода или Dockerfile:

```bash
docker compose -f compose.yml up --build -d
```

### Перезапустить только приложение

```bash
docker compose -f compose.yml restart app
```

### Посмотреть состояние контейнеров

```bash
docker compose -f compose.yml ps
```

### Следить за логами в реальном времени

```bash
docker compose -f compose.yml logs -f
```

### Полностью удалить контейнеры вместе с данными PostgreSQL

**Внимание:** следующая команда удаляет Docker volume проекта и все хранящиеся в нём данные PostgreSQL.

```bash
docker compose -f compose.yml down -v
```

Используйте её только тогда, когда действительно хотите сбросить состояние базы данных.

## Устранение неполадок

### Порт `8000` уже занят

Сообщение может выглядеть так:

```text
ports are not available: ... 127.0.0.1:8000
```

Остановите локально запущенный Uvicorn или измените `APP_PORT` в `.env`, например:

```dotenv
APP_PORT=8001
```

Затем пересоздайте конфигурацию контейнеров:

```bash
docker compose -f compose.yml up --build -d
```

После изменения порта API будет доступен по адресу `http://localhost:8001/docs`.

### Ошибка `exec format error`

Проверьте окончания строк файла `docker/entrypoint.sh`. Для Linux-контейнера используйте формат LF.

В Git Bash можно выполнить:

```bash
sed -i 's/\r$//' docker/entrypoint.sh
```

Убедитесь, что первая строка файла:

```sh
#!/bin/sh
```

После исправления пересоберите образ:

```bash
docker compose -f compose.yml up --build -d
```

### Приложение не запускается

Посмотрите логи:

```bash
docker compose -f compose.yml logs --tail=200 app
```

Проверьте состояние сервисов:

```bash
docker compose -f compose.yml ps
```

### PostgreSQL не становится готовым

Посмотрите логи базы:

```bash
docker compose -f compose.yml logs --tail=200 postgres
```

Проверьте настройки `POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD` в `.env`, а также состояние контейнера PostgreSQL.

### Фоновая задача не выполняется

Посмотрите логи приложения:

```bash
docker compose -f compose.yml logs --tail=300 app
```

Проверьте, что Celery Worker, Celery Beat и Redis запущены. Если Worker не может подключиться к брокеру, проверьте значение `REDIS_URL` и адрес Redis.

### API не возвращает данные

Проверьте, что контейнеры запущены, миграции применены, а задача сбора цен успешно выполнилась. При необходимости повторите запрос к API после следующего запуска задачи.

## Хранение данных

Данные PostgreSQL сохраняются в именованном Docker volume `postgres_data`, который создаётся Docker Compose. Поэтому обычные команды `stop`, `start` и `down` не удаляют сохранённые цены.

Для полного сброса данных требуется явное удаление volume командой `docker compose -f compose.yml down -v`.

## Примечания

- Для получения цен используется публичный API Deribit (https://docs.deribit.com/).
- Redis используется как брокер Celery, а не как основное хранилище цен.
- PostgreSQL хранит данные между перезапусками контейнеров.
